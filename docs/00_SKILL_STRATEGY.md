# Skill Strategy for AI Data Quality PoC

## Always-on baseline

- `karpathy-guidelines`

## Use by workflow

- `systematic-debugging`: first response to bugs, failing tests, or unexpected behavior.
- `root-cause-tracing`: deep failures where the original trigger is unclear.
- `test-driven-development`: implementing each feature/bugfix with a failing test first.
- `verification-before-completion`: before claiming work is complete or fixed.

## Optional quality bias skills

- `mattpocock-clean-code-mini`: readability, naming, and function clarity.
- `mattpocock-clean-architecture-mini`: boundary and dependency discipline.
- `mattpocock-code-complete-mini`: implementation hygiene and engineering rigor.

## Selection guidance

- Start with one baseline skill and one task-specific skill.
- Add at most one optional quality-bias skill for a given ticket.
- Remove skill pressure if it conflicts with explicit project constraints in `AGENTS.md`.
